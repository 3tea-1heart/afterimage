# 余像 AFTERIMAGE

一个开源的浏览器图像工坊，面向摄影成片、meme 与复古风格、轻量平面设计。以「一键风格配方」为入口，同时保留图层、参数、文字和原始图片，可自由调整与组合；全部在本地浏览器运行、无需上传。

当前版本 **V14.0**（文档更新于 2026-11-09）。历次版本与修复详见文末「更新日志」。

> 本文档同时是功能总览与更新历史入口；未完成、未验证或未发布的部分都会以文字明确标注。

## 快速开始

1. 安装 [Node.js](https://nodejs.org/)。启动器会自动查找可用的 `node`。
2. 双击 [Start-Afterimage.cmd](outputs/Start-Afterimage.cmd)，保持服务窗口开启。
3. 在浏览器访问 <http://127.0.0.1:4173/>。推荐使用支持 Canvas 与 MediaRecorder 的桌面 Chrome / Edge。
4. 导入照片，选中图层，再应用风格配方或模板。
5. 编辑结束前点击“保存工程”；需要成片时点击“导出作品”。

也可以在项目根目录运行：

```powershell
node outputs/local-server.cjs
```

不要直接双击 `index.html`，应用使用 JavaScript 模块，需要 HTTP 服务。若 4173 端口被占用，先确认是否已经启动了本项目。编辑内容会自动保存在本机浏览器，重新载入后继续；重要作品仍建议用“保存工程”导出 JSON 备份。

### 桌面版（Windows）

```powershell
npm install
npm run dist:win
```

产物为 `release/Afterimage-14.0.0-setup.exe`（安装包）与 `release/win-unpacked/AFTERIMAGE.exe`（免安装目录）。安装包未签名，首次运行可能出现 SmartScreen 提示。开发调试可直接 `npm start`，或 `npm run serve` 后用浏览器访问。

### 安卓版（Capacitor）

安卓工程位于 `android/`，Web 资源由 `npx cap sync android` 同步进 `android/app/src/main/assets/public`。本机未安装 JDK 与 Android SDK，因此本地不构建 APK；推送 `v*` 标签后由 `.github/workflows/release.yml` 在 GitHub Actions 上执行 `./gradlew assembleDebug`，产出 debug 签名 APK。需要正式签名时自行配置 keystore 并改用 `assembleRelease`。

### 网页版（GitHub Pages）

`.github/workflows/pages.yml` 在推送 `main` 后把 `outputs/afterimage-studio/dist` 发布到 Pages。仓库设置里需把 Pages 的来源选为 GitHub Actions。网页版需要首次联网加载，未注册 Service Worker。

## V14 新操作

- 图层 → “♫ 音乐播放卡”：编辑封面、曲名和歌手；导入本地音频后可播放，点击“记录当前进度到画面”保存卡片的显示进度。

- 工程标签“＋ 新建” → 空白画布尺寸/背景/透明；历史 → “回到手动保存”保留当前分支。关闭改动工程先询问是否保存。
- 设置 → 五套配色或自定义，素材栏左右布局、舒适/紧凑密度，快速缩略图。修改后点击“保存并关闭”。
- 动态页 → 游动折射镜 / 窗光流帘 / 高光呼吸光轨 / 放映机微动；也可在配方中搜索玻璃漫游、午后光帘、午夜镜头、私人放映。

## 物件工坊

V12新增真实PBR播放器、自定义GLB、多页阅读编辑与物件WebM导出。完整范围与未完成项见[历史需求核对表](outputs/afterimage-studio/REQUIREMENTS.md)。

从顶部“物件工坊 ◇”进入。先选中照片或组合，更新封面，选择物件与专属介质预设。直接拖动物件转动、滚轮缩放、双击翻面或开合；CD 也可拖动下方开合把手。细参数位于「精调与内容来源」。修改完成后点“保存物件设置到工程”，关闭面板后再“保存工程”导出 JSON。需要平面排版时使用“放入编辑器为图片层”；需要成片时在工坊内导出 PNG。工坊支持一个当前物件配置，二维成片可添加多层。

## 编辑工作流（V14）

- 右侧「图层」→「新建调整图层」：胶片颗粒、色彩平衡、曲线、对比度/调色、色阶。调整作用于下方合成画面，可独立改参数、强度、顺序、可见性和蒙版。曲线与色彩平衡默认中性。
- 左侧「修复 J」：选择图片后点击/涂抹污点；Alt 点击指定取样源；[ / ] 改直径。支持融合修复、仿制、强度和清除当前层笔触。修复点独立保存，不改原图；长边最高4096，每层500点上限。
- 拖动工具栏/素材栏/检查器的竖边界改宽度，拖动画布与时间轴、检查器与色板的横边界改高度；双击边界恢复默认，聚焦边界后方向键微调。窄屏另有画布/素材/检查器区域的底边高度把手。设置中可恢复全部面板尺寸。
- 顶部工程标签支持新建、切换、关闭和最近关闭重开；每个工程保留自己的视图与历史，浏览器刷新可恢复。
- 右侧「历史」显示分支树。返回旧节点后继续编辑保留旧分支；输入名称点「保存编辑节点」即可随时回到关键版本。工程JSON携带当前工程的分支/节点，图片素材去重复；其他工程不会混进此文件。关闭标签不删除本机自动保存内容。
- 所有当前和历史请求统一维护在 [TODO.md](TODO.md)，勾选项与验证证据对应。其余拟物与完整视频/音频剪辑的欠项保留未勾选。

## 当前功能

代码核对数量：**76 种参数化效果、88 套风格配方、8 种版式模板、11 类组合贴片**。数量统计以 `engine.js`、`templates.js` 为准；模板不计入滤镜配方数量。

### 风格与图像处理

- 摄影：基础曝光、对比度、饱和度、冷暖、胶片、颗粒、柔焦、高光柔晕、暖色溢光、局部色光、晕影、留银、镜头呼吸（桶形变形 + 边缘色散 + 暗角）等。
- 复古与动态：CRT、RGB 分离、像素化、抖色、信号故障、色相循环、漏光、液晶屏翻拍与旧数码压缩。
- 印刷与实验：双色/三色映射、半调、复印、线雕、套印偏移、墨扩散、纸纹、像素排序、ASCII、镜像与干涉色膜等。
- 美术处理：油画色块、浮世绘木版风限色。属于算法风格化，不是生成式重绘，也不等同真实手绘。
- 支持效果开关、顺序调整、参数调整及颜色选择。
- 新效果默认作用于选中图层；全画面处理需明确选择“整幅作品”。应用配方会替换当前作用范围的效果链，保留其他图层的效果。

### 图层与排版

- 图片、文字、符号贴片与基础形状；图层隐藏、锁定、排序、复制、删除。
- 画布拖动、四角缩放、旋转手柄；位置、尺寸、透明度、投影及混合模式。
- 自由文字、环形文字、乱码文字；对齐、换行、行距、字形横向宽度、描边、颜色与发光（半径 + 颜色）。
- 图片替换可保留模板位置和尺寸；模板照片使用等比裁切填充。
- 矩形/椭圆蒙版：位置、尺寸、羽化、反相；不会破坏图层原图。
- 基础调色、色阶、五点分段线性曲线、色彩平衡。

### 时间轴与动态

- 图层片段的入点、出点、淡入、淡出。
- 拖动片段中间移动时间位置，拖动两端裁时长；时间编辑精度为 0.05 秒。
- 漂浮、呼吸缩放、轻摇和显隐预设；位移、旋转、缩放往返循环。
- 关键帧：在当前播放头一键记录位置、旋转、缩放与不透明度（最多 60 帧），支持平滑 / 线性 / 定格三种缓动，时间轴上以菱形标记并可直接跳转或删除；至少两帧时接管该图层的动画，覆盖运动预设。
- 关键帧数值栏：选中时间轴上的关键帧后可直接输入 X / Y / 旋转 / 缩放 / 透明度，边改边渲染。
- 拖动同步关键帧：图层已有关键帧时，在画布上拖动、旋转或用对齐按钮改位置，会把这批关键帧的 X / Y / 旋转按同一增量整体平移，整条运动路径跟着走，不再只改基准变换而看起来“拖不动”。
- 支持播放、定位和步进；默认折叠，点击“时间轴”展开。
- 当前是静态图层的动态编排，不是完整视频剪辑器；没有视频源裁切、音轨编辑或自由曲线（贝塞尔）编辑。

### 搜索、取色与预览

- 风格、效果、图层、元素和模板检索；配方分类与收藏。
- 风格展厅、大图试映、前后款切换、原图对比与分类联系表导出。
- 画布取色、近似主色提取、HEX 输入、收藏颜色与色板 JSON 导出。
- 配方缩略图长边 112；展厅缩略图 144；大预览先生成 160，再细化到最高 2048。
- 工作画布可选长边 360 / 600 / 1000；导出尺寸独立于工作预览质量。拖动滑块、播放动画或拖拽画布时自动按当前档位的 0.7 倍出图，停手约 160 ms 后补一帧全分辨率。
- 图层级效果结果带缓存：姿态、时间、画质不变时整层像素处理直接复用，拖动、缩放、播放与拖动时间轴都不会重跑效果；缓存最多保留 12 张图层位图。
- 专注模式与可展开的效果库。

### 保存与导出

- 工程 JSON：保存图片、图层、效果、蒙版、修复笔触、运动、时间参数与历史分支/命名节点，可再次打开继续编辑。
- 静态输出：PNG、JPEG、WebP；最长边最多 4096。画质可选 0.94 / 0.86 / 0.72，JPEG/WebP 生效。
- 动态输出：WebM（VP9，回退 VP8），最长边最多 1200；支持 WebCodecs 时离线逐帧编码后由自研封装器写 WebM，无需保持页面在前台、帧率恒定；不支持 WebCodecs 的浏览器自动回退到 `MediaRecorder` 实时录制（该路径仍要求前台运行）。
- 动图输出：GIF89a，离线逐帧渲染 + 自研编码器（固定 6×6×6 调色板、LZW 压缩、循环播放）；长边最多 480，帧率随总时长在 4–15 fps 间自适应，最多约 120 帧。
- GIF 抖动可在导出对话框选择三档：默认「误差扩散」（Floyd–Steinberg，蛇形扫描，渐变更平滑、体积更大）、「有序抖动」（4×4 Bayer，网点规律、体积更小）、「不抖动」（直接取最近色阶，色块感最明显但体积最小）。
- 导出时显示进度并可取消；静态画质选项同时按比例影响 WebM 码率。
- 导出的静态图、GIF 与 WebM 逐帧渲染在独立 Worker（OffscreenCanvas）中完成，主线程只负责显示与编码，导出时界面不再被逐帧渲染卡住；Worker 加载或渲染失败会自动回退主线程。
- 树形历史撤销/重做、保留分支、命名编辑节点、多工程标签；常用快捷键包括 Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z、Ctrl/Cmd+D、Delete 和方向键。
- 收藏配方与色板保存在当前浏览器；草稿自动保存在 IndexedDB，工程文件仍建议手动导出。

## 已知限制与质量状态

- 目前主要使用 Canvas 2D / CPU 处理，未实现 WebGL 加速；大图、油画统计和多层复杂效果可能较慢。V10.6 只把导出渲染移入 Worker，画布预览与播放仍在主线程。V10.12 的图层效果缓存消掉了「同一层反复重算」的开销，但作用范围为「整幅作品」的效果仍在每帧重新执行一遍像素循环，这类效果在 600 px 预览下约 50–60 ms/帧。
- 手机翻拍、旧数码、油画和木版均是视觉模拟；不能以功能测试通过代替参考图的质感验收。
- 拼贴尚无自动抠图、真实撕纸材质或透视变形；蒙版尚无画笔编辑。
- 不支持 MP4 导出、音频轨道和完整关键帧编辑；GIF 已支持（固定 256 色、长边 480、帧率 4–15 fps）。关键帧只覆盖位置、旋转、缩放与不透明度，缓动为三种预设，没有贝塞尔曲线、图形编辑器和按属性分轨。
- 文字外观依赖可用字体；V10.14 起西文字体自托管（latin 子集，共 263 KB），中文走系统字体链，因此不同系统的中文衬线观感会不同；断网时西文字体仍可用。
- 本地图片在浏览器中处理，不会由当前应用上传到服务器。工程 JSON 包含原图与保留历史分支中的图片（包括当前画面已删的图片）；仅分享成片时可使用 PNG/JPEG。
- V8 已有部分实际浏览器检查；V10.1 只做了 Node 渲染与隔离 DOM 回归，尚未做真实浏览器的视觉与交互验收。
- V10.2 的浮动工具条、双击内联编辑、配方强度、A/B 对照与追加模式只在隔离 DOM 环境验证，真实浏览器下的光标定位与触摸板手感尚未验收。
- V10.5 的 WebM 使用 Canvas 逐帧 `requestFrame` 调度（不支持时回退到 30 fps 自动采样），仍受页面是否在前台影响，未使用 WebCodecs 离线编码，也未实现 MP4。
- GIF 编码器为自研实现：固定 6×6×6 调色板、一种 LZW 压缩策略，抖动提供误差扩散 / 有序（4×4 Bayer）/ 关闭三档；没有局部调色板、透明帧与调色板优化，渐变与细腻肤色仍会有可见色阶。误差扩散按通道独立量化（调色板是规则立方体，等价于逐通道最近色阶），不是三维最近邻搜索；它把噪点扩散到周围像素，细密纹理比有序抖动更不规则，体积也明显更大（同内容实测约 2.15 MB 对 1.33 MB）。
- GIF 与 WebM 导出在 Chromium 下完成了端到端下载验证（GIF 480×240 / 45 帧 / 1.13 MB，WebM 3 秒 / 30 fps / 0.09 MB，控制台无报错）；下载文件的播放器兼容性与移动端表现尚未验收。
- V10.6 的导出 Worker 在 Chromium 中确认被实际加载（服务端日志有 `render-worker.js`、`engine.js`、`surface.js` 请求），静态 PNG 与 GIF 导出成功且无控制台错误；Worker 内的文字使用系统字体链，若后续引入自定义字体需要另行处理。首次导出需要额外生成并转移图片位图，会有一次性的启动延迟。
- 循环量化只覆盖带“每循环圈数”参数的周期效果（色相循环、万花筒、玻璃、波纹、棱镜分条、干涉）；颗粒、故障、CRT 等按速度推进的效果在循环点不保证无缝。
- V10.3 的模板专属字段、字形宽度/发光控件与三个新镜头效果仅在隔离 DOM 和 Node 渲染下验证，真实浏览器的排版观感尚未验收；模板字段按图层名称与内容长度启发式命名，不保证与实际语义一致。
- V10.9 的拖动同步关键帧只处理 X / Y / 旋转的等量平移：组选时其余成员按同一 dx/dy 处理而不是按各自缩放比例换算；属性面板的 X / Y 输入框与不透明度滑块仍直接写图层基准值，有关键帧时不会改动关键帧，需要改这些属性时请用关键帧数值栏；缩放（宽高）仍只改基准尺寸，对整段动画统一生效。
- V10.10 的离线视频编码依赖 WebCodecs（Chromium 94+、Safari 16.4+ 等）；不支持时静默回退到 `MediaRecorder` 实时录制，那条路径仍要求页面保持前台且帧率受机器影响。输出只有 VP9 / VP8 WebM，没有 MP4 与音轨；码率按画质档位固定估算（约 6.4 Mbps × 画质），不做内容自适应。整段编码的压缩数据留在内存里，超长或超高分辨率片段会显著占用内存。新封装器只在 Chromium 下完成了解码回读验证，Firefox / Safari 的 `VideoEncoder` 输出兼容性尚未验收。
- V10.11 的误差扩散在导出时按帧同步计算，480×240 单帧约 14 ms（Node 实测），全部帧仍在导出流程内完成，不额外占用常驻内存；但体积上误差扩散明显大于有序抖动，长片导出需要权衡。抖动方式选择只保留在当前对话框，不写入工程文件，重新导出需再次选择。Firefox / Safari 与移动端的 GIF 解码一致性未验收。
- V10.12 的缓存按「图层内容 + 效果链 + 输出尺寸 + 时长 + 时间桶」比对字符串，参数或尺寸变化即失效，判定本身有少量字符串拼接开销；缓存只保留 12 张图层位图，超大图层连续调参时会反复淘汰。播放与拖动时的降分辨率是 0.7 倍（600 档约 420 px），暂停后约 160 ms 才回到全分辨率，期间画面会先「软」一下。应用配方后配方缩略图延后 800 ms 重建，这段时间其他卡片的缩略图仍是旧画面。全幅效果、蒙版羽化与文字排版不在缓存范围内。Chrome 之外的浏览器、移动端与高分屏未做本轮的帧率验收。
- V10.13 的美术层是纯装饰，不改变处理与导出结果。字体经 Google Fonts 加载（Syne / Instrument Serif / Noto Serif SC / Space Mono），断网时回退到系统字体，排版宽度会变；全屏噪点、环境光与自绘光标在 `prefers-reduced-motion` 下关闭或降级，触屏设备不启用自绘光标。1024 px 宽 Chromium 实测正常；800 px 宽只补充了不换行 / 横向滚动的栅格规则，未取得可信的窄屏截图与逐项人工验收。风格展厅的逐张显现依赖 `IntersectionObserver`，不支持时会直接显示全部卡片。（V10.14 已把 Google Fonts 外链改为自托管 woff2 子集。）
- V10.14 的 Windows 安装包未做代码签名，SmartScreen 可能提示“未知发布者”；也没有接入自动更新，升级需要重新下载安装包。安装包约 116.7 MB，主要是 Electron 运行时。
- 安卓 APK 目前只有 debug 签名，适合侧载安装，不适合直接上架应用商店；正式发布需自备 keystore 并切换 `assembleRelease`。本机没有 JDK / Android SDK，APK 只由 GitHub Actions 构建，未在真机或模拟器上做安装与交互验收，安卓端的导出落盘、分享与性能仍属未验证状态。
- 安卓 WebView 的能力随系统版本差异较大：WebCodecs 在较旧 WebView 上可能不可用，此时 WebM 导出会回退到 `MediaRecorder` 实时录制；`Directory.Documents` 在 Android 10 及以下需要存储权限，代码里已请求并在失败时回退浏览器下载。
- 自托管字体只包含 latin 子集，中文仍依赖系统字体，因此不同设备的中文排版宽度不完全一致。
- GitHub Pages 版本没有 Service Worker，首次打开必须联网，断网后无法离线启动；Electron 与 APK 版本则是本地打包资源，可离线使用。
- 打包后的 Electron 使用自定义 `afterimage://app/` 协议加载资源，因此页面里的 `fetch`/模块/Worker 路径都以应用内根目录为基准；直接双击 `dist/index.html` 仍不可用。
